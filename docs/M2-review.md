# M2 短切片｜給評審的說明

分支：`expedition-m2`（疊在 `expedition-m1` 上；不合併、不部署）。開關預設關閉，網址加 `?exp=1` 才有入口。

**順序說明：** PLAN 規定 M1 先過 Fable 5.2 正式評審再開 M2。維護者要求先把內容做出來，所以 M2 是在 M1-R 還沒開的情況下做的。M1 和 M2 都還沒有經過獨立評審，也都沒有真人試玩。

## 做了什麼

| 項目 | 內容 | 檔案 |
|---|---|---|
| 路線 | 熱身草原（鯉魚王，搶 5）→ 岔路（雨天池塘／招財巷，搶 5）→ 補給營地 → 強風山口（大蔥鴨，搶 7）→ 龍之巢（快龍首領） | `content.ts` |
| 場地規則 | 水窪（預警 1 秒）、黃金球（發球前明示，2 分）、強風（預警 1 秒顯示方向）。每場最多一項 | `field.ts` |
| 卡牌 | 6 張、卡槽 2 個、贏球三選一（不重複、牌池不足就少給）、補給站換裝 | `content.ts`、`cards.ts` |
| 羈絆 | 雷、風各一條，同標籤湊 2 個發動，上場的夥伴算一個 | `cards.ts` |
| 收服 | 熱身、菁英、首領首次必中；岔路 60%，失敗一次後下次保底。結果由種子決定，落在結算那一筆 | `logic.ts` |
| 首領 | 玩家 5 滴血、快龍 7 滴血；快龍剩 3 滴時，下一球發球前預告，之後球速 ×1.10 | `field.ts` |
| 隊伍 | 上場 1 隻加備援 1 隻，在地圖上可以換誰上場 | `logic.ts` |
| 畫面 | 手繪路線地圖（天色隨進度從清晨到夜晚）、收服演出、夥伴提示、旅行日誌、圖鑑、通關明信片（可存成圖片） | `art.ts`、`ui.ts`、`widgets.ts` |

每一輪有一個由種子決定的名字（例如「起霧的遠征 #AAA8」），地圖上的雲和星星位置也跟著種子走。這些只是外觀，不影響規則。

## 跟 SPEC 不一樣的地方（需要維護者確認）

1. **沒有「能量」。** 遊戲本體沒有能量這個東西。SPEC 的電氣球、蓄勢、雷羈絆原本是「能量取得」，這裡改成作用在「撲救距離」：電氣球 ×1.12、蓄勢 ×1.18（殺球 ×0.96）、雷羈絆 ×1.08。
2. **隊伍滿了不問要不要換。** SPEC 寫隊伍滿時由玩家選擇替換或只記入收藏；現在一律只記入圖鑑。
3. **電腦強度逐站調整。** SPEC 寫初版難度固定。這裡每一站有固定的一組強度（腳步、殺球機率、慢半拍機率），越後面越強，數值沒有試玩依據。
4. **起始夥伴 7 隻。** 依維護者的決定，四隻起始角色加關都御三家。
5. **首領第二階段的球速做法。** 每 10 幀讓球多走一步，而且只在球離地面、球網、牆、角色都夠遠時才多走，所以實際加速略低於 ×1.10。碰撞一律走遊戲本體原本的那一步。

## 驗證

| 項目 | 結果 |
|---|---|
| `npm test` | 28 個測試全過（M1 的 17 個改寫後保留，新增 11 個） |
| 開關關閉、或開關打開但沒在遠征比賽中 | 跟 main 逐幀比對：一般對戰 5/5、冠軍之路 2/2 一致 |
| 整輪通關 | 瀏覽器走完一輪：贏、收服、三選一、岔路、補給站換裝、風羈絆、首領兩階段、通關、明信片 |
| 黃金球 | 第 3 球比分從 1:1 變 3:1 |
| 卡牌跳躍倍率 | 輕羽加風羈絆：跳躍高度 155.8（原本 136，預期 ×1.1448 = 155.7） |
| 機率收服失敗 | 可達鴨跑掉，`captureMissesByCharacter.psyduck = 1`，畫面顯示下次必中 |
| 首領戰輸 | 玩家 5 滴血扣完算輸，心 3 → 2，留在首領那一站 |
| 比賽結束後還原 | 場地色調、計分板、勝分、移動倍率都回到原值 |
| 舊的 M1 存檔 | 讀到舊內容版本：顯示「不支援」、原檔不動，可匯出或另存後開新的一輪 |

瀏覽器裡的勝負是用腳本把球放到某一邊的地上做出來的，不是真人打的。

## 還沒驗證

- 真人試玩（PLAN M2 的通過條件全部跟真人有關：完成時間、能不能說出對策、想不想再玩）。
- 手機實機：面板在小螢幕的排版、切 App、轉向。
- 水窪把球彈起來的那一下：規則照冠軍之路的寫法，但這次在瀏覽器裡沒有剛好打到。
- 強風在瀏覽器裡的實際推球效果（只確認了比賽能打完）。
- 英文、韓文頁面的排版（文字都有，型別檢查通過，沒有逐頁看）。
- 所有數值（卡牌倍率、電腦強度、收服機率、首領血量）。
