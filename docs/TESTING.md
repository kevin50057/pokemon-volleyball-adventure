# 怎麼驗證

| 指令 | 做什麼 | 大約多久 |
|---|---|---|
| `npm test` | 型別嚴謹度檢查，加上規則與存檔的單元測試（75 個，不開瀏覽器） | 5 秒 |
| `npm run e2e` | 先 build，再用無頭瀏覽器跑下面六項 | 2 分鐘 |
| `npm run verify` | 上面兩個都跑 | 2 分鐘 |

`npm run e2e` 需要電腦上有 Chrome 或 Edge（不會另外下載瀏覽器）。只跑其中幾項：`node e2e/run.mjs soak daily`；想看畫面加 `--headed`。

## 瀏覽器測試的六項（`e2e/run.mjs`）
1. **開關關閉**：沒有遠征的入口和面板，也沒有開遠征的資料庫。
2. **逐幀基準**：10 組角色各打 3000 幀，每一幀的狀態雜湊要跟 `e2e/parity-golden.json` 一樣。用來確認改遠征沒有動到一般對戰。
3. **重整與失焦**：比賽中重整，回來是同一場、不扣心；按住方向鍵時視窗失焦，比賽暫停、按鍵清空、面板關不掉，其他分頁也有「繼續」。
4. **整輪**：電腦代打從第一章打到通關。每一步之後存檔都要讀得回來、不能卡死；通關後重整，紀錄還在。
5. **每日遠征**：打完記一筆、連續 1 天；主線那一輪原封不動；沒有新的永久收服。
6. **壓測**：24 隻都在覺醒狀態下，打各種場地規則和三個首領（超夢另外從第 2、3 階段開始），共 48 場。不能卡死，打完技能數值和勝分要還原。

## 逐幀基準什麼時候要更新
故意改了一般對戰的行為（角色技能、物理）時，第 2 項會失敗。確認是預期的改動後：
```
node e2e/run.mjs parity --update
```
把更新後的 `e2e/parity-golden.json` 一起提交。**沒有打算改一般對戰卻失敗，就是改壞了。**

## 測不到的
- 好不好玩、難度、每章要打多久：要真人。
- 需要玩家特定操作才會觸發的覺醒：小火龍（空中按住上）、胖丁（空中按下殺球）、水伊布（撲救留水窪）、火伊布（大字爆得分）。電腦不會這樣打，壓測只列出發動次數，不判定這幾隻。喵喵改的是計分，也沒有判定。
- 實體手機：切 App、來電、轉向、觸控。
- 快轉時主控台會出現音效解碼的錯誤（main 也有），測試會略過這一類。
